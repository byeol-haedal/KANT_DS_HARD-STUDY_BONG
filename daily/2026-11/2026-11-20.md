## 오늘 배운 것 — 모델 평가

### 1. 혼동 행렬 (Confusion Matrix)
- 분류 모델의 예측을 **실제값과 예측값의 짝**으로 세어 놓은 표

| | 예측 1 (Positive) | 예측 0 (Negative) |
|---|---|---|
| **실제 1** | TP (맞게 양성이라 함) | FN (양성인데 음성이라 함) |
| **실제 0** | FP (음성인데 양성이라 함) | TN (맞게 음성이라 함) |

- 이름 읽는 법 : 뒤 글자(P/N)는 **모델이 뭐라고 예측했는지**, 앞 글자(T/F)는 **그 예측이 맞았는지**
- 공식 문서 : [sklearn.metrics.confusion_matrix](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.confusion_matrix.html)

### 2. 분류 성능 평가 지표

| 지표 | 묻는 것 | 공식 |
|---|---|---|
| 정확도 (Accuracy) | 전체 예측 중 맞힌 비율 | (TP + TN) / 전체 |
| 정밀도 (Precision) | **양성이라고 예측한 것 중** 실제 양성의 비율 (환자로 예측한 사람 중 실제 환자) | TP / (TP + FP) |
| 재현율 (Recall, 민감도) | **실제 양성 중** 모델이 찾아낸 비율 | TP / (TP + FN) |
| 특이도 (Specificity) | **실제 음성 중** 음성이라고 맞힌 비율 (환자가 아닌 사람을 아니라고 한 비율) | TN / (TN + FP) |
| F1 Score | 정밀도와 재현율의 **조화 평균** | 2 × P × R / (P + R) |

- 정밀도와 재현율은 분모가 다르다. 정밀도는 **예측** 기준(세로), 재현율은 **실제** 기준(가로)이다.

#### 직접 계산해 보기
실제와 예측 10쌍을 세면 TP 4, FN 2, FP 1, TN 3

| 지표 | 계산 | 값 |
|---|---|---|
| Accuracy | (4 + 3) / 10 | 0.70 |
| Precision | 4 / (4 + 1) | 0.80 |
| Recall | 4 / (4 + 2) | 0.67 |
| Specificity | 3 / (3 + 1) | 0.75 |
| F1 | 2 × 0.80 × 0.67 / (0.80 + 0.67) | 0.73 |

### 3. F1 Score는 왜 필요한가
- **불균형 데이터**에서는 정확도만으로 성능을 평가하기 어렵다.
  - 예 : 100명 중 환자가 1명이면, 모두 "환자 아님"이라고만 해도 정확도가 99%다. 그런데 환자는 한 명도 찾지 못했다.
- F1은 조화 평균이라 **낮은 값에 더 큰 가중치**를 준다. 정밀도와 재현율 중 하나만 높아서는 F1이 높게 나오지 않는다.
- F1이 1에 가까우면 정밀도와 재현율이 모두 높다. 낮으면 둘 중 하나(또는 둘 다)가 낮다.
- 거짓 양성(FP)과 거짓 음성(FN)의 중요성 사이에서 균형을 잡아야 할 때 쓴다.

### 4. classification_report 읽기
- 어떤 클래스를 Positive로 정하느냐에 따라 정밀도·재현율 값이 달라진다. 그래서 리포트는 클래스 0과 1 각각의 지표를 따로 보여준다.
- **macro avg** : 클래스별 지표를 단순 평균
- **weighted avg** : 클래스별 샘플 수를 가중치로 두고 평균

### 5. 클래스 불균형 데이터 처리
- 한 클래스의 샘플이 다른 클래스보다 현저히 많거나 적으면, 모델이 다수 클래스 쪽으로 치우쳐 학습해 소수 클래스를 잘 못 맞힌다.

| 접근 | 방법 |
|---|---|
| 데이터 레벨 | **오버샘플링** : 소수 클래스를 늘린다 (SMOTE로 합성 샘플 생성) / **언더샘플링** : 다수 클래스를 줄인다 (데이터 손실 주의) |
| 알고리즘 레벨 | 소수 클래스에 **가중치**를 더 준다 / 앙상블 기법 |
| 평가 지표 | 정확도만 보지 말고 정밀도, 재현율, F1을 함께 본다 |
| 기타 | 소수 클래스를 잘 구별하는 특성을 고른다 (Feature Selection) |

## 오늘 배운 것 — 파이썬 실습 (주택 가격 CSV)

### 1. CSV 파일 읽기
- 첫 줄인 `ID,size,year,price`는 열 이름(헤더)이다. 실제 데이터는 그 아래 10줄이다.
- 따라서 전체 행 수는 10이 나와야 한다. 11이 나온다면 헤더까지 집계한 것이다.
- `DictReader`는 첫 행을 키 값으로 읽기 때문에 데이터 행으로 취급하지 않는다.

```python
import csv

with open("1.01.house.price.csv", encoding="utf-8") as f:
    df_house = list(csv.DictReader(f))

print(df_house[0])     # 첫 번째 행 (딕셔너리)
print(len(df_house))   # 길이 = 개수 = len
print(type(df_house[0]['price']))   # <class 'str'> : CSV에서 읽은 값은 모두 문자열
```

- `utf-8`은 파일에 저장된 숫자(바이트)와 글자를 서로 바꾸는 규칙(인코딩)이다.
- `with`는 `open`으로 연 파일을, 들여쓴 부분이 끝나는 순간 대신 닫아준다. `f`는 내가 부여한 이름이다.
- `with` 없이 쓰면 직접 닫아야 한다. 이때 괄호를 잊지 말 것 : `f.close()`
- 오타 조심할 것. 띄어쓰기도 글자다.

### 2. 예외 처리 — try / except
- `try` = 일단 해볼 코드 / `except 에러이름` = 그 에러가 나면 대신 할 코드

```python
try:
    with open("1.01.house.price.csv", encoding="utf-8") as f:
        df_house = list(csv.DictReader(f))
    print(df_house[0])
    print(len(df_house))
except FileNotFoundError:
    print("파일명과 업로드 여부를 확인하세요.")
```

- **실험** : `print`를 `try` 밖에 두면, 안내 문구가 나온 뒤 에러가 나야 한다. 그러나 Colab에서는 앞 셀에서 이미 `df_house`를 정의했기 때문에 에러가 드러나지 않는다. **가장 위험한 에러다.**
- 그래서 `print`를 `try` 안에 넣는다. 파일을 제대로 읽었을 때만 결과를 출력하기 위해서다.

### 3. 문자열을 숫자로 바꾸기

```python
houses = []
excluded = 0

for i, row in enumerate(df_house, start=1):   # i : 몇 번째 행인지
    try:
        house = {
            "ID": int(row["ID"]),
            "size": int(row["size"]),
            "year": int(row["year"]),
            "price": float(row["price"])
        }
        houses.append(house)
    except ValueError:
        print(f"{i}번째 행 제외: 숫자로 바꿀 수 없는 값이 있습니다.")
        excluded += 1

print(f"저장한 행 수: {len(houses)}")
print(f"제외한 행 수: {excluded}")
```

- 변환하면 숫자에 붙어 있던 따옴표가 사라진다. str(문자열)에서 int(정수)로 바뀌었기 때문이다.
- price는 int가 아니라 float(실수)로 바꿨기 때문에 5가 아니라 5.0이 출력된다.
- `"오류"`처럼 숫자가 아닌 글자, `""`처럼 비어 있는 값은 `int()`에서 `ValueError`가 난다. 그 행은 `append`까지 가지 못하고 `except`로 넘어간다.
- 한 행에서 오류가 나도 반복문은 멈추지 않고 다음 행을 계속 처리한다.
- **except가 제대로 동작하는지는 일부러 틀린 값을 넣은 테스트 데이터로 확인했다.**
- 대소문자, 괄호 종류(`()`, `[]`, `{}`)를 구분할 것
