## 오늘 배운 것 — AI 리터러시

### 1. AI · ML · DL
- **인공지능** : 컴퓨터가 학습, 추론, 판단, 문제 해결 등 지능적인 작업을 수행할 수 있도록 하는 기술을 연구하는 컴퓨터 과학 분야
- **머신러닝** : 사람이 규칙을 직접 정의하는 대신, 데이터를 통해 패턴을 학습하고 이를 바탕으로 예측이나 분류 등을 수행하는 기술
- **딥러닝** : 인공 신경망을 이용해 데이터의 특징을 학습하는 머신러닝의 한 분야. 이미지·음성·자연어 같은 복잡한 데이터 처리에 널리 활용
- 딥러닝은 무엇이 깊은 걸까? **레이어가 깊은 것이다.**

### 2. 지도학습과 정답 데이터
- **ML의 대부분은 지도학습이다!!!**
- 정답 데이터를 먼저 봐야 한다.
- 생존 분석일 경우 0이 얼마인지, 1이 얼마인지 확인한다. 소수값이 3:7보다 작으면 불균형 데이터다.
- 회귀는 값 하나, 분류는 특정 집단에서 하나 고르기
- GPT도 거칠게 따지면 분류 모델이다. 기존에 정해진 어휘 안에서 가장 확률 높은 것을 고르는 것이다.
- 가장 잘 설명할 수 있는 방법은 기획적 방법이다.

### 3. 선형 모델과 비선형 모델
- SST가 가장 작은 선형 모델이 수학적으로 가장 적합하다.
- 이것이 잘 작동하는지 비교하기 위한 **베이스라인 모델은 평균**이다.
- 꼭 직선이어야 하나? 곡선일 경우를 **비선형 모델**이라고 한다.
- 선형 모델이 더 쉽고 간단하다. 선형 모델의 가성비로 해결할 수 있다면 가장 좋지만, **일상은 대부분 비선형의 문제로 채워져 있다.** (주가, 날씨, 판매 예측 등)
- 딥러닝은 비선형 모델이다.

### 4. 모델의 학습
- 첫 번째 노드를 입력층이라고 한다.
- 우리가 건드릴 수 있는 건 **weight밖에 없다.** 최대한 비슷하게 맞추려고 노력하는 것을 **함수 근사**라고 한다.
- 파라미터의 초기값은 아무 의미 없는 무작위 숫자다. 초기값 설정에 고민이 많다.
- **AI의 지능은 가중치에 학습된다. 이것이 영업비밀.**
- **TASK** : 모델이 해야 할 일, 모델의 목표

### 5. LLM
- LLM은 서비스 관점에서 **자연어 입력**이라는 큰 변화를 가져왔다. 언어의 이해, 검색과의 차이, 생산성 차이는 수십~수백 배
- **스케일링 법칙(Scaling Law)** : 파라미터가 맞으려면 학습 데이터가 충분히 많아야 한다. 경험적인 발견 = 돌려 보고 알게 된 것
- **Emergent ability** : 학습 데이터의 양이나 모델의 크기가 임계점을 넘을 때 예기치 않게 나타나는 새로운 능력
- 같은 질문에도 답이 다른 이유 : 무조건 가장 높은 확률의 단어를 고르는 것이 아니라, 상위 2~3개 후보 중에서 고르기도 하기 때문
- 벡터 공간 = 좌표 공간
- 딥시크가 주목받은 이유 : 강화학습으로 훨씬 적은 비용으로 고성능 결과를 냈다.

> **기술적 추동력이 사회적 상상력을 앞서는 시대에 살고 있다.**
> AI 시대에 직업적으로 필요한 것이 무엇인지 생각해야 한다.

### 6. 할루시네이션
- 사실과 다른 정보를 생성하거나, 학습 데이터에 없는 내용을 만들어내는 현상. 여전히 존재한다.
- 정보를 압축하면서 유실되는 부분이 생겨 할루시네이션이 생긴다.
- **AI는 '답'이 아니라 '확률 높은 패턴의 답'을 생성한다는 것을 유의해야 한다.**

### 7. 프롬프트 엔지니어링
- 프롬프트는 단순한 질문이 아니다. AI에서 원하는 결과를 얻기 위해 프롬프트를 만들고 최적화하는 과정

| 구분 | 의미 | 주체 |
|---|---|---|
| Instruction Tuning | 지시를 이해하는 능력 | 모델 |
| In-Context Learning | 프롬프트로 추론하는 능력 | 모델 |
| Prompt Engineering | 프롬프트를 잘 설계하는 기술 | 사용자 |

흐름 : 프롬프트 입력 → Instruction Tuning 기반 "요청 이해" → In-Context Learning 기반 "패턴 추론" → 결과 생성

**프롬프트 5요소** — 입력 3개(역할, 맥락, 명령) / 출력 2개(형식, 어조)
- **역할 Role** : AI가 수행할 입장이나 역할
- **맥락 Context** : AI가 이해할 수 있도록 충분한 배경 정보
- **명령 Instruction** : 원하는 결과를 얻기 위한 구체적인 지시
- **형식 Format** : 결과물의 형태와 구조
- **어조 Tone** : 결과물의 말투, 분위기, 스타일

**더 나은 결과를 위한 전략 — 명확한 지시를 작성하라**
> 모델은 당신의 마음을 읽을 수 없다. 모델이 의도를 추측해야 하는 부분이 적을수록 원하는 결과를 얻을 가능성이 높아진다.
- 질문에 세부 사항을 포함하기 / 역할(페르소나) 맡기기 / 구분 기호 쓰기 / 단계 명시하기 / 예시 주기 / 출력 길이 명시하기

| 나쁜 예 | 좋은 예 |
|---|---|
| 회의록을 요약해 줘. | 회의록을 한 문단으로 요약해 줘. 그다음 발언자별 핵심 내용을 마크다운 목록으로 정리하고, 다음 단계나 실행 항목이 있다면 나열해 줘. |

# 🎯 커리어 · 취업 특강
> **강상훈 데이터분석가** — 알파고 이전부터 딥러닝 연구, 다양한 조직과 직무를 경험

<br>

### 💬 느낀 점
- 직무와 각 직무별 역량에 대해 깊이 알 수 있었다.
- 나는 **데이터분석가 혹은 기획가 타입**이라는 것을 느낄 수 있었다.
- **SQL과 파이썬**을 준비해야 한다는 것을 확인했다.
- 막막하다면 **관심 분야 도메인의 종사자에게 접촉해 보라**는 조언은 매우 적확하다고 느꼈다.

<br>

### 1. 데이터를 둘러싼 직무
> 세상은 너무 빨리 바뀌지만, 본질은 변하지 않는다.

- 예전에는 데이터 관련 업무를 하는 사람 모두가 데이터 사이언티스트였고 혼자 다 했지만, 이제는 세분화된 **팀플레이**다.
- 데이터는 결국 큰 엑셀이다.

| 직무 | 하는 일 |
|---|---|
| 데이터 분석가 | 관리된 데이터를 추출하고, 분석(예 : 시청 이탈 패턴)하고, 시각화(대시보드 등)한다. |
| 데이터 과학자 | 데이터로 추천 등 모델을 만든다. |
| 데이터 엔지니어 | 데이터 인프라를 구축한다. 데이터를 어떻게 추출·변환·적재할지 고민한다. 백엔드 엔지니어에 가깝다. |

- 직무 명칭은 회사마다 다르다. **채용 공고 속 키워드로 필요한 역량을 직접 읽어야 한다.**

### 2. 데이터 사이언티스트의 두 갈래

| | 리서치 중심 | 서비스 중심 |
|---|---|---|
| 하는 일 | 특정 기술의 고도화 | 만들어진 모델을 서비스에 맞게 튜닝하고 적용 |
| 공고 특징 | 기술만 적혀 있음. 리서처, 리서치 사이언티스트 | 서비스 이름이 적히고, 서비스·산업군 이해를 강조 |
| 요구 | 논문을 읽고 이해하고 구현하는 능력 (주로 석박사) | 프로그래밍 능통, 엔지니어링 경험. 학력은 크게 중요하지 않음 |

- 데이터 사이언티스트를 리서치 중심으로만 오해하는 경우가 많다.
- 내가 어떤 성향에 적합한지 스스로 질문해 봐야 한다.

### 3. 데이터 애널리스트
- **가장 학습하기 어려운 것은 인사이트 도출**이다. 인사이트는 도메인 지식에서 나오기 때문에, 커리어를 시작한 도메인 안에서 이직하는 경우가 많다.
- 비즈니스 분석가, 그로스 해커, PM, 퍼포먼스 마케터 공고에서도 데이터 분석 역량을 요구한다.
- **SQL SQL SQL**

### 4. 공통으로 요구되는 역량
모든 걸 다 잘할 필요는 없지만, 공통 역량은 분명히 있다.

| 역량 | DS | DA |
|---|---|---|
| 데이터 모델링 | ✔ | |
| 컴퓨터 사이언스 기초 | ✔ | |
| 통계 지식 | ✔ (통계 자체를 알아야) | ✔ (통계 활용을 알아야) |
| 기획력 | ✔ | ✔ |

- **데이터 모델링을 잘한다** = 어떤 상황에 어떤 기법과 평가지표가 적절한지 아는 것
- 큰 착각 : 모델링만 잘하면 된다? 모델링은 전체 과정의 일부일 뿐, 모델링 역량만 요구하는 공고는 없다.
- 부트캠프는 하드스킬 위주라서, **"왜 좋은지, 왜 작동하는지, 왜 하는지"** 에 집중해야 한다.

**모델링 학습 방법** : 이론 → 구현(코딩 경험) → 한 프로젝트를 처음부터 끝까지 경험
- 구현 경험 추천 순서 : 인턴 > 대회(캐글, 데이콘 등) > 공모전 = 프로젝트
- 백문이 불여일견, 백견이 불여일행

**알고리즘 코딩 테스트**
- 얼마나 효율적인 코드를 짜는지 확인한다. 데이터가 커질수록 차이는 더 커진다.
- 모든 기업이 요구하지는 않지만, 순수 IT 기업은 본다. 대비하면 지원할 수 있는 회사의 폭이 넓어진다.
- **무조건 파이썬 해라.**

### 5. 인사이트와 기획력은 어떻게 키울까?
> 강의로 해결되는 부분이 아니다. 내가 그 분야를 좋아해야 궁금증이 생기고, 궁금증이 많아야 인사이트가 생긴다.

- **인사이트 역량 = 가설을 세우는 능력.** 상상력이 필요하다.
- 상상은 서비스와 고객에 대한 깊은 이해에서 시작되고, 그 이해를 가설과 시나리오로 만들 수 있으면 좋은 분석가가 될 준비가 된 것이다.
- **일 잘하는 데이터 분석가는 그 도메인을 잘 아는 사람이다.**
- 아무것도 모른다면, 서비스를 이용하는 사람에 대해 고민하며 소설을 써 봐라. 물론 소설을 안 써도 될 만큼 잘 아는 도메인에 지원하는 게 가장 좋다.

**숨겨진 직무 — 데이터 기획자**
데이터가 서비스가 될 때, 하나의 서비스에 오너십을 가지고 고객 분석과 디자인을 포함해 기획·개발·출시·운영 전 과정을 매니징하는 사람. 일명 **미니 CEO**. 요구 역량은 데이터 분석가와 비슷하다.

### 6. Q&A
- **필수 역량** : SQL, 파이썬, 통계 지식. SQL만 알아도 인턴 레벨 업무는 바로 시작할 수 있다.
- **대기업 vs 스타트업** : 첫 연봉이 매우 중요하기에 대기업을 목표로 할 것 같다. 단, 성장 가능성이 폭발적이고 정말 좋은 사수가 있다면 스타트업도 나쁘지 않다.
- **(내 질문) 막막하다면 어떻게 하시겠어요?**
  > 최대한 내가 목표로 하는 곳에 있는 사람들과 접촉할 것 같다. 사람들은 생각보다 친절하다. 계속 도움을 청하고 물어봐라. 구글링하면 생각보다 쉽게 찾을 수 있으니 메시지를 보내 봐라. 이게 가장 좋은 방법이다.
- 협업 역량, 인사이트, 기획력은 이력서로 증명할 수 없다.
- **AI 검증은 결국 일에서 드러난다. 설명도 못 하면 신뢰는 바닥이다.**
